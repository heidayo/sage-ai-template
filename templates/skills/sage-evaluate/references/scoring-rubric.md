# 6軸 詳細採点基準

## ① Codified Rules（満点20点）

### 満点条件（20点）
- CLAUDE.md / `.claude/rules/` への具体的なルール連携が定義されている
- Forbidden Shortcuts（禁止事項）が明示されている
- 機械的ゲート（lint/CI/hook）でルール違反を自動検出できる
- File Scope（修正可能ファイル）が明示されている

### 減点トリガー
| 問題 | 減点 |
|------|------|
| CLAUDE.md/rules への連携が抽象的（「適切に」「正しく」など） | -3 |
| Forbidden Shortcuts の明示がない | -3 |
| 機械的ゲート（lint/CI/hook）がない | -4 |
| File Scope が定義されていない | -4 |
| Error Resolution 手順への言及がない | -3 |
| commit-msg hook（TASK-ID必須）への言及がない | -2 |

---

## ② Atomic Decomposition（満点20点）

### 満点条件（20点）
- 各タスクが単一責任で分解されている
- 依存グラフが明示されている（A→B→C並列等）
- 各タスクの完了条件がコマンドで検証できる
- 並列実行可能なタスクが明示されている

### 減点トリガー
| 問題 | 減点 |
|------|------|
| タスクが複数レイヤーにまたがり独立していない | -4 |
| 依存グラフがない（実行順序が不明） | -4 |
| 完了条件が「目視確認」など主観的 | -4 |
| 並列実行可能かどうか不明 | -3 |
| タスクの粒度が大きすぎる（File Scope > 10ファイル） | -2 |
| TASK-IDが振られていない | -3 |

---

## ③ Spec-Driven Development（満点20点）

### 満点条件（20点）
- SPEC-IDが振られている
- 受け入れ条件が正常系・異常系の両方で書かれている
- 受け入れ条件が具体的なコマンド/テストで検証可能
- Out-of-scope（対象外）が明示されている

### 減点トリガー
| 問題 | 減点 |
|------|------|
| SPEC-IDがない | -5 |
| 受け入れ条件が片方向のみ（正常系のみ、または異常系のみ） | -3 |
| 受け入れ条件がコマンドで検証できない | -4 |
| Out-of-scope（対象外）が「なし」または未記載 | -3 |
| タスクの記述が3行以下で具体性が著しく低い | -3 |
| セキュリティ要件への言及がない | -2 |

---

## ④ Observable Development（満点20点）

### 満点条件（20点）
- 各フェーズに具体的な検証コマンドがある
- テスト種別（unit/integration/e2e）が明示されている
- フィードバックサイクルが明文化されている
- 検証方法セクションに具体的な手順がある

### 減点トリガー
| 問題 | 減点 |
|------|------|
| 検証方法が「目視確認」のみ | -5 |
| フェーズごとの検証コマンドがない | -4 |
| テスト種別（unit/integration/e2e）の指定がない | -3 |
| カバレッジ閾値への言及がない | -3 |
| Quality Gate（5段階）との対応が不明 | -2 |
| 本番→開発へのフィードバックループがない | -2 |

---

## ⑤ Knowledge Management（満点15点）

### 満点条件（15点）
- `sage/failures.md` との連携が設計されている
- Error Resolution 手順がある（エラー時に何をするか）
- `sage/anti-patterns.md` の参照がある
- 新規パターン発見時の蓄積フローがある

### 減点トリガー
| 問題 | 減点 |
|------|------|
| failures.md への言及がない | -4 |
| Error Resolution 手順がない | -4 |
| anti-patterns.md の参照がない | -2 |
| 新規失敗パターンの蓄積フローがない | -2 |
| リスクが1つも挙げられていない | -3 |

---

## ⑥ 段階採用戦略（加点最大5点）

### 加点条件
- 既存コードへの影響ゼロ戦略がある: +2点
- 段階的に適用できる設計がある: +1点
- ロールバック手順が明記されている: +1点
- 影響範囲が最小限に抑えられている: +1点

---

## グレード基準

| スコア | グレード | 判定 |
|--------|---------|------|
| 100 | S++ | 完璧。即実装可。「このまま実装を開始してください」と明示 |
| 95-99 | S+ | ほぼ完成。微修正で到達可能 |
| 90-94 | S | 優秀。小改善あり。改善後に実装推奨 |
| 85-89 | A- | 良好。改善推奨。改善してから実装 |
| 70-84 | B | 基本OK。要改善。改善必須 |
| ~69 | C | 大幅改善必要。実装前に再設計 |

---

## 自動修正の優先順位

スコアが低い場合、以下の順で修正する（効果が大きいものから）：

| 優先度 | 修正内容 | 典型的な効果 |
|--------|---------|------------|
| 1 | SPEC-ID / TASK-ID の付与 | +5〜8点 |
| 2 | 受け入れ条件の具体化（コマンド追加） | +4〜7点 |
| 3 | Out-of-scope の明示 | +3点 |
| 4 | 依存グラフの追加 | +4点 |
| 5 | File Scope の明示 | +4点 |
| 6 | Error Resolution 手順の追加 | +4点 |
| 7 | 検証コマンドの追加 | +4点 |
| 8 | failures.md / anti-patterns.md 連携 | +4〜6点 |
| 9 | リスクの追加 | +3点 |
| 10 | セキュリティ要件の追加 | +2点 |
