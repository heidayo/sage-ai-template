# Installer カスタマイズ保全ガイド (SPEC-0026)

`bash install.sh` によるテンプレート更新時に、プロジェクト固有のカスタマイズがどう守られるか・守られないかをまとめたガイドです。更新前バックアップからの手動復元手順と、マーカー方式の限界（防御されないケース）を記載します。

## 更新前バックアップ

installer は UPDATE 対象（既存かつ内容が変わる）ファイルを、書き込み前に自動で `.sage/backup/<UTC タイムスタンプ YYYYMMDD-HHMMSS>/` へ元の相対パス構造のまま保存します。

- 保持世代数は**直近3世代**。4世代目の作成時に最古の世代ディレクトリが自動削除されます（削除対象はタイムスタンプ形式 `YYYYMMDD-HHMMSS[-N]` のディレクトリのみ。手動で置いたファイル等は削除されません）
- 同一秒内の連続実行では `-N` suffix（例: `20260702-084337-1`）が付与され、既存世代は上書きされません
- UPDATE が 0 件の実行、および `--dry-run` / `--diff` ではバックアップは作成されません
- `.sage/backup/` は gitignore 対象です（リポジトリにはコミットされません）
- `.sage/backup/` が書き込み不可の場合、installer はファイルを一切上書きせずエラー終了します（fail-safe）

### 更新前の差分プレビュー

更新を実行する前に、何が変わるかを確認できます（書き込みは一切行われません）:

```bash
bash install.sh --diff
```

CLAUDE.md / AGENTS.md の diff にマーカー外の行が現れた場合、それ自体が保全違反（マーカー破損等）のシグナルです。更新前に必ず原因を確認してください。

## 手動復元手順

更新でカスタマイズが失われた場合、最新のバックアップ世代からコピーして復元します:

```bash
# バックアップ世代の一覧（名前昇順 = 古い順）
ls -1 .sage/backup/

# 最新世代から対象ファイルを復元
cp .sage/backup/<最新timestamp>/<ファイル> <ファイル>

# 例: CLAUDE.md を復元する
cp .sage/backup/20260702-084337/CLAUDE.md CLAUDE.md
```

復元後は、消失の原因（マーカー破損・managed ファイルへの直接追記等）を確認し、必要なら issue を起票してください。

## マーカー方式で防御されるケース / 防御されないケース

CLAUDE.md / AGENTS.md は `<!-- === SAGE Development System (auto-injected) === -->` 〜 `<!-- === End SAGE === -->` のマーカー間だけを installer が管理します。マーカーの状態によって挙動が異なります。

| ケース | 更新時の挙動 | カスタマイズ | 対処 |
|:-------|:------------|:------------|:-----|
| マーカー正常（両方存在） | マーカー間のみ置換。マーカー外は不変 | ✅ 防御される | 不要 |
| 片方欠損（開始 or 終了のみ） | **更新されない**（上書きも append もせず WARN を出してスキップ） | ✅ 内容は守られるが SAGE セクションが更新されない | マーカーを手動修復してから再実行 |
| 両方欠損（旧フォーマット / 完全手動ファイル） | 末尾に SAGE セクションが **append される**（既存行は不変。消失はしないが旧記述と重複し得る） | ⚠️ 防御されないケース（重複が発生し得る） | 重複した旧 SAGE 記述を手動で削除 |
| 旧フォーマット（マーカー導入前の SAGE 記述あり） | 両方欠損と同じく append。旧記述はそのまま残り重複する | ⚠️ 防御されないケース | 旧記述を削除しマーカー付きセクションに一本化 |
| マーカー内への手動編集 | 更新時にマーカー間ごと**全置換され消える** | ❌ 防御されないケース | マーカー外（上部）または `.claude/rules/local/` に移す。消えた場合はバックアップから復元 |

いずれのケースでも、内容が変わる書き込みの前にはバックアップが取得されるため、`.sage/backup/` から復元できます。
